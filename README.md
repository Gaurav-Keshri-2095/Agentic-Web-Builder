# AI Web Builder

## Overview
AI Web Builder turns a single prompt into a complete, multi-file web project. It exists to eliminate repetitive scaffolding and let teams validate ideas quickly with a working codebase generated by a structured, multi-agent pipeline.

## Demo / How It Works
1. User submits a prompt in the frontend.
2. Planner agent converts the prompt into a structured project plan.
3. Architect agent decomposes the plan into implementation steps.
4. Coder agent generates all files using structured output schemas.
5. Backend returns the generated files to the frontend.
6. Frontend renders a file explorer and supports ZIP download.

## Architecture
### Planner Agent
Transforms the user prompt into a `Plan` schema (name, description, tech stack, features, and file list) using structured LLM output.

### Architect Agent
Converts the `Plan` into a `TaskPlan` with ordered `ImplementationTask` steps, still using structured output. This removes ambiguity and avoids free-form JSON parsing.

### Coder Agent
Generates the complete codebase using a `CoderOutput` schema. Files are returned as `{ path, content }` objects, then sent to the frontend without additional parsing.

### Data Flow
Prompt -> `Plan` -> `TaskPlan` -> `CoderOutput` -> FastAPI `/generate` -> React UI -> ZIP download.

### Why Structured Output
The pipeline uses Pydantic schemas with `json_mode` structured output. This prevents brittle JSON parsing, reduces tool failures, and enforces consistent contracts between backend and frontend.

## Tech Stack
- Backend: Python, FastAPI, LangGraph
- AI: LLM with Pydantic structured output (LangChain + Groq client)
- Frontend: React (Vite), Tailwind CSS
- File handling: JSZip + file-saver (client-side ZIP generation)

## Folder Structure
- agent/ - Planner/Architect/Coder logic, prompts, and state schemas
- backend/api.py - FastAPI server exposing `/generate`
- frontend/ - React UI (file explorer, prompt input, ZIP download)
- main.py - Minimal entry point

## Setup Instructions
### Backend
1. Create a virtual environment:
   - `python -m venv .venv`
   - Windows: `.venv\Scripts\activate`
   - macOS/Linux: `source .venv/bin/activate`
2. Install dependencies:
   - `pip install -e .`
3. Set environment variables (required for Groq LLM access):
   - Create `.env` at repo root with `GROQ_API_KEY=...`
4. Run the API:
   - `uvicorn backend.api:app --reload --port 8000`

### Frontend
1. Install dependencies:
   - `cd frontend`
   - `npm install`
2. Start the dev server:
   - `npm run dev`

Optional environment variable:
- `VITE_API_BASE` to override the backend URL (defaults to `http://localhost:8000`).

## API Endpoint
### POST /generate
Request body:
```json
{
  "prompt": "Build a personal finance tracker"
}
```

Successful response:
```json
{
  "success": true,
  "files": [
    { "path": "README.md", "content": "..." },
    { "path": "src/main.ts", "content": "..." }
  ]
}
```

Error response:
```json
{
  "success": false,
  "error": "Code generation failed",
  "details": "..."
}
```

## Features
- Multi-agent pipeline (Planner -> Architect -> Coder)
- Structured output enforcement with Pydantic schemas
- Dynamic codebase generation from a single prompt
- File explorer UI with syntax-aware display
- Client-side ZIP download of generated files
- FastAPI error handling with clear response contracts

## Challenges & Learnings
- JSON parsing failures and tool_use_failed errors were common with free-form output.
- Enforcing structured output via Pydantic schemas stabilized agent behavior.
- Frontend-backend contract mismatches were reduced by centralizing types.
- Keeping the pipeline deterministic required separate LLM settings per agent.
